# Dependency optimization audit

## Scope and method

Compared the completed TanStack Router baseline at origin/main commit
06f5ae5d10ffc60b03398b9ca8417405f4a4102f with the isolated implementation
worktree. The baseline and candidate used Bun 1.4.4, the locked dependency
graph, Node 24.19.0, and the same four-core host.

origin/main advanced to b52aa02fd8f02147eb43337e4cf34037c3426867 (PR #336)
while the release gate was running. The audit and implementation remain based
on the measured PR #335 snapshot; the dirty worktree was not rebased.

The inventory covers all nine workspace manifests, bun.lock, root and package
scripts, Vite and Tailwind configuration, source imports, tests, configuration,
generated route inputs, and CI usage. A package-name reference scan was
followed by manual checks for dynamic imports, CLI/config use, framework
plugins, generated routes, peers, and type-only declarations. The scan found
no unused remaining declarations. React type packages are consumed implicitly
by JSX and compiler configuration.

Bundle sizes come from Vite production builds and their manifest. Route sizes
include the HTML entry's static imports plus the selected route module's static
imports; later user-triggered lazy modules are excluded. Gzip figures below
are reproducible Bun gzip level 9 estimates, not measured HTTP transfer bytes.
Cold-cache build timing and real network transfer could not be isolated.

## Findings and decisions

### Radix UI and Base UI

The six remaining Radix packages are actively used by the web component
wrappers: checkbox, dialog, dropdown menu, select, tabs, and tooltip. The
shared UI package does not currently provide feature-equivalent Base UI
components for all of them. A broad migration would affect controlled state,
portals, focus, keyboard behavior, and component styling, so it was deferred.
The isolated Label wrapper was safe to replace with the platform label element.

### TypeScript and Bun declarations

TypeScript 7.0.2 remains the CLI typechecker through @typescript/native.
TypeScript 5.9.3 remains direct at root and web: the root architecture checker
uses its compiler API, and openapi-typescript has a TypeScript 5 peer range.
Replacing either compiler would risk tooling and peer compatibility without a
measured benefit.

Each relevant workspace retains bun-types. Only the database's redundant
@types/bun forwarding package was removed.

### Build and optional tooling

Turbo stays because CI runs cached workspace tasks and
scripts/test-turbo-invalidation.ts checks task invalidation. Bun scripts alone
do not provide the same task cache. @tanstack/intent remains required by the
repository's skill instructions and root scripts. Router generation remains
required by the file-based route setup. Router Devtools are development-only
and gated by import.meta.env.DEV, so they are excluded from production builds.

ExcelJS and @e965/xlsx have separate XLSX and legacy XLS responsibilities.
Chart.js and react-chartjs-2 provide the chart engine and its React adapter.
pdf-lib, jszip, Drizzle, Elysia, TypeBox, and workspace packages all have
runtime or boundary-specific use. No further direct dependency was found to
be safely removable.

The lockfile still has multiple versions where package ranges or peer contexts
require them. The postcss 8.5.23 vs 8.5.31 split was removed. Bun's dedupe
check reports no remaining dedupeable duplicates.

Build and typecheck samples ran on the same four-core machine. The measured
build ranges were 2.002–2.949 s baseline and 1.783–3.145 s final, so the
apparent median improvement is not treated as a reliable performance gain.
Cold-cache build time was not isolated. The API benchmark used production mode,
the current synthetic SQLite schema, a disposable OPERATOROS_DATA_DIR, and no
ambient DATABASE_URL. Browser wire transfer was not captured; gzip-9 values
are estimates.

The meaningful runtime saving is in the Dashboard route graph and its emitted
chunk. Login's initial graph is smaller by about 1.2% compressed. The largest
shared entry chunk grew slightly as Vite rebalanced chunks, despite the lower
total JS. Server startup and memory did not materially change.

## Validation

- Frozen Bun install passed with no lockfile changes.
- TypeScript 7 CLI typecheck, Bun native checks, architecture boundary checks,
  and the focused Label/Form tests passed.
- The complete release gate passed in 1,077 seconds. It ran two backend passes
  of 419 tests each, fresh database parity, package and OpenAPI checks, frontend
  production builds, the 8-scenario backend smoke, 59 browser scenarios, and
  3 readiness scenarios. E2E disposable artifacts were cleaned after success.
- The route tree was regenerated by the production build. OpenAPI drift,
  TypeBox resolution, import boundaries, auth/session behaviors, export
  formats, SQLite integrity, and recovery checks passed within the release gate.
- A clean production-only frozen install installed 188 packages; the API started
  against a disposable current-schema SQLite database and returned HTTP 200
  from /ready with persistence reported as sqlite.
- Separate Markdown layout/link checks and root lint/typecheck checks are
  recorded after this page was added.

## Remaining opportunities and risks

1. Profile the 407 kB raw / 123 kB gzip-9 index chunk and its eager imports.
   It remains the largest first-route cost; use a measured, route-level
   split only if query/session and TanStack Router behavior remain covered.
2. Consider converting the remaining Radix wrappers to Base UI one component
   at a time after shared UI APIs cover their current behavior. The potential
   dependency and bundle saving is larger than the isolated Label change, but
   so is the accessibility and interaction regression risk.

No dependency change affected API contracts, authentication, database
initialization, SQLite safety, or document download routes. Actual browser
transfer compression and cold-cache build time remain unmeasured.
